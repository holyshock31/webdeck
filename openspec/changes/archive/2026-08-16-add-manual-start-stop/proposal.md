## Why

目前本地服务的启动依赖「打开应用标签时自动拉起」（startOnOpen 勾选）或工具栏上针对**当前选中应用**的 ▶/⏹ 按钮：未激活的应用无法单独启动/停止，必须先切换到该应用才能操作；而工具栏按钮在未选中应用时被禁用，操作路径不完整。用户希望任何应用都能随时手动启动/停止，不再需要跑到终端里手动拉起本地服务。

另外存在一个缺陷：工具栏 ▶/⏹ 对「启动方式 = 无」（纯远程应用）并未禁用，此时点 ▶ 会以空命令 spawn 并报错，按钮语义与配置不符。

## What Changes

- 侧边栏每个应用项新增独立的 ▶/⏹ 手动控制按钮：可对**任意应用（含未激活的）**启动/停止本地服务，无需先切换标签，点击按钮不改变当前选中项
- 按钮图标与标题随状态实时切换：停止/错误/未知 → ▶「启动本地服务」；启动中/运行中 → ⏹「停止本地服务」
- 「启动方式 = 无」的应用（无本地进程可管理）按钮禁用，悬停提示原因，修复现状下空命令 spawn 报错的问题
- 启动/停止语义幂等：已运行再点启动不重复拉起进程；未运行再点停止为无害 no-op；启动失败（spawn 错误/超时/异常退出）后可再次手动启动重试
- 复用现有 IPC（app:start / app:stop）、进程组终止逻辑与健康监测状态机，不新增持久化字段、不改变 startOnOpen 自动启动与 stopOnQuit 退出清理行为
- 范围：新增能力；验收方式为手动验证

## Impact

- **主进程**：app:start / app:stop 处理器保持现有行为，核对并补强幂等保证（已运行不重复启动、未运行停止返回 ok 不产生副作用）
- **渲染层**：列表项新增控制按钮（点击 stopPropagation 不触发标签切换），工具栏 ▶/⏹ 保留并与列表按钮状态一致；样式沿用 styles.css 主题变量
- **状态/监测**：完全复用 apps:status 推送与现有状态机（starting / running / error / stopped），无新增状态、无新 IPC 通道
- **持久化**：无 schema 变化，webdeck.json 读写与旧版本完全兼容
- **兼容性与风险**：低；不改变自动启动、退出清理、编辑/删除联动；对无启动配置应用从「点 ▶ 报错」变为「按钮禁用」，行为更符合直觉
- **验收**：npm test 与 npm run smoke 无回归，另附手动验证清单（见 tasks.md）
