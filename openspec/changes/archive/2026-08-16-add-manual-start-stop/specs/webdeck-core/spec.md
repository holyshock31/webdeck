# WebDeck Core Specification

## ADDED Requirements

### Requirement: 侧边栏应用项提供手动启动/停止控制

侧边栏每个应用项内置独立的启动/停止按钮（▶ 启动、⏹ 停止），可对**任意应用**（含当前未激活的）手动启动或停止本地服务：点击按钮只作用于该应用，不切换当前标签、不改变选中项；「启动方式 = 无」（无本地进程可管理）的应用按钮禁用并悬停提示原因；按钮状态随运行状态切换，与工具栏的 ▶/⏹ 一致。

#### Scenario: 不切换标签直接启动未激活应用的本地服务

用户当前打开应用 A，点击应用 B 侧边栏项上的 ▶，B 的本地服务被拉起，B 的状态灯由灰变黄（starting）再变绿（running），当前标签仍停留在 A，B 未被激活。

#### Scenario: 停止未激活应用的本地服务

用户点击应用 B 项上的 ⏹（B 未激活），B 的本地进程组被终止，B 的状态灯变为灰（stopped），当前标签与选中项不变。

#### Scenario: 无启动配置的应用按钮禁用

用户选中一个「启动方式 = 无」的纯远程应用，其项上的 ▶/⏹ 按钮为禁用态，悬停提示「该应用未配置本地启动」，点击无任何效果，也不产生进程或报错。

### Requirement: 手动启动/停止的幂等与可重试语义

手动启动在应用已在运行时是幂等操作：不重复拉起进程、不重置日志与状态；手动停止在应用未运行时为无害 no-op；启动失败（spawn 错误、启动超时、进程异常退出）后状态进入 error，用户可再次点击 ▶ 重新启动，无需重启 WebDeck 或删除重建应用。

#### Scenario: 重复点击启动不产生重复进程

用户对正在运行的本地服务连续多次点击 ▶（或启动中再次点击），只存在一个进程实例，日志不重复清空，状态灯仍正常进入 running，不出现端口占用等冲突。

#### Scenario: 对未运行的应用点击停止无副作用

用户对状态为 stopped（本地服务未启动）的应用点击 ⏹，状态保持 stopped，不产生错误提示，日志面板行为不变。

#### Scenario: 启动失败后可重新手动启动

应用配置的启动命令不存在（spawn 失败），用户点击 ▶ 后状态变为 error 并显示原因；用户修正命令（编辑应用）后再次点击 ▶，本地服务正常启动并进入 running。

### Requirement: 手动控制状态实时反馈

启动/停止按钮与状态灯随 apps:status 推送实时更新，无需刷新界面；同一应用在侧边栏列表项按钮与工具栏 ▶/⏹ 显示的动作始终一致；手动启动或停止后，底部状态栏与状态灯立即反映最新状态。

#### Scenario: 按钮随状态推送自动切换

用户点击 ▶ 后按钮立即变为 ⏹；健康检查通过进入 running 后按钮保持 ⏹；用户点击 ⏹ 停止后按钮自动变回 ▶，全程无需手动刷新。

#### Scenario: 列表按钮与工具栏动作一致

用户选中应用 A 后，A 的列表项按钮与工具栏 ▶/⏹ 显示相同动作（同为 ▶ 或同为 ⏹）；对未选中应用 B 手动启动后，B 的列表项按钮变 ⏹，工具栏仍反映选中应用 A 的状态，互不干扰。
