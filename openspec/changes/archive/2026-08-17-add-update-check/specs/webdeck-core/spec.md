# WebDeck Core Specification

## ADDED Requirements

### Requirement: 更新检查与提示

打包版（安装版）提供更新检查能力：主进程按调度自动检查（启动延迟后首查、固定周期 ± 随机抖动、失败指数退避），也可由用户在设置/关于区域手动触发。**自动检查静默**（发现新版本时提示、无更新或失败时不打扰）；**手动检查明确反馈**（无更新提示"已是最新"，失败给出错误）。检查结果与下载进度经 IPC 实时更新 UI。

#### Scenario: 启动后自动检查发现新版本

用户启动打包版 WebDeck，自动检查发现 GitHub Releases 有更高版本，界面出现"有新版本"提示（含版本号）；若没有新版本则无任何打扰。

#### Scenario: 手动检查无更新

用户在设置/关于区域点击"检查更新"，没有新版本时明确提示"已是最新版本"。

#### Scenario: 自动检查失败不打扰

网络不可用时自动检查失败，不弹窗不打扰，仅按退避策略延后重试；用户手动检查时才会看到错误提示。

### Requirement: 更新安装的平台分派

更新安装按平台形态分派：**Windows 安装版**走完整自动更新——检查到新版本后下载（显示进度），下载完成由用户点击"立即安装"才执行静默安装并重启（绝不随退出自动安装）；**macOS（未签名）与 portable 版**不做自动安装——检测到新版本时提示并提供"打开下载页"（跳转 GitHub Releases）作为更新途径；portable 版不发起自动检查。

#### Scenario: Windows 安装版自动更新全链路

Windows 用户打开 WebDeck，检测到新版后自动下载并显示进度；下载完成弹出更新对话框，用户点击"立即安装"，应用退出 → 静默安装 → 自动重启进入新版本。

#### Scenario: 退出 WebDeck 不自动安装

Windows 用户下载完成但未点击"立即安装"，随后退出 WebDeck——应用正常退出，不静默安装更新（更新保留，下次启动可继续）。

#### Scenario: macOS 提示打开下载页

macOS 用户检测到新版本，界面提示"有新版本"并提供"打开下载页"按钮，点击后系统浏览器打开 GitHub Releases 页面，不执行自动安装。

#### Scenario: portable 版不自动检查

Windows portable 版用户打开应用，不发起自动更新检查、不显示更新入口，更新方式为手动下载新版本。

### Requirement: 更新检查失败可恢复

更新检查/下载失败不破坏当前版本：下载中断可取消、错误经 IPC 上报（仅手动场景提示）、自动调度按指数退避重试；安装仅在用户确认后触发。

#### Scenario: 下载失败不影响使用

Windows 用户更新下载中断（断网/取消），应用功能不受影响，手动"检查更新"可重新发起下载。
