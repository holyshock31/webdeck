# Proposal — fix-activate-no-reload

## Why

侧边栏点击应用（`apps:activate`）走 `activateApp()`，其中 `view.webContents.loadURL(appCfg.url)` 位于任何条件分支之外（`src/main/index.js` L335），**每次激活都会对已存在的视图发起一次完整导航**——切换应用、甚至重复点击当前应用，都会把目标页面整体刷新一遍，页面内滚动位置、表单输入、SPA 状态全部丢失。对 DSH GUI 这类有状态应用，等于每次切换都被重置。刷新有专属入口（工具栏 ↻ / ⌘R），侧边栏切换不应隐式重载页面。该行为自初始提交起存在，且**切换应用时刷新目标页面并不在规格中**（spec 仅要求"重复点击回到首页 URL"——本次一并移除，见下）。

## What Changes

- `activateApp()` 不再无条件 `loadURL`：仅在**首次创建视图**或**配置的 URL 与视图已加载 URL 不一致**（应用编辑改了 URL）时发起加载；其余激活（切换标签、重复点击当前应用）只切换/聚焦视图，不重新加载页面
- 移除既有行为"重复点击当前应用回到首页 URL"（无任何点击触发页面刷新；需要刷新时用工具栏 ↻ 或 ⌘R）
- 保留加载失败/渲染进程崩溃时的自愈：页面加载失败（`did-fail-load` 非 ABORTED）或渲染进程崩溃后，下一次激活该应用时重新加载，避免用户停在错误页无路可走（加载失败重试不构成"点击刷新正常页面"）
- 对应修改既有规格 `webdeck-core` 的「多应用标签与登录态隔离」：删除"重复点击回到首页 URL"，新增"切换标签不重新加载目标应用页面（保留页面状态）"语义
- 不改变：会话分区隔离、状态监测、菜单/快捷键切换、查找栏关闭逻辑、冒烟测试流程（均对新建应用做首次激活，首次激活仍加载）

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `webdeck-core`: 「多应用标签与登录态隔离」要求变更——删除"重复点击回到首页 URL"，改为"侧边栏/快捷键/菜单切换标签均不重新加载目标应用页面，页面状态保留；重新加载走工具栏 ↻ / ⌘R 或（失败/崩溃后）重新激活"

## Impact

- **代码**：`src/main/index.js` 的 `activateApp()`（L316-356）与 `createView()`（L98-147）——视图记录已加载 URL 与加载失败标志；`did-fail-load` / `render-process-gone` 处理器补记失败/崩溃标志
- **规格**：`openspec/specs/webdeck-core/spec.md` 增量（上述要求与两个场景：快捷键切换标签、重复点击行为）
- **行为变化**：切换/重复点击应用不再刷新页面（主要修复）；编辑应用 URL 后激活仍会加载新 URL（保持现状）；加载失败/崩溃后激活会重试（保持现状的自愈能力）
- **风险**：极低——冒烟测试与 e2e 均不依赖"激活即重载"语义；`did-finish-load` 监听在首次激活时仍触发
