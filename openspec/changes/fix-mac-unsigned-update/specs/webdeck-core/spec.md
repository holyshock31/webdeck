## MODIFIED Requirements

### Requirement: 更新安装的平台分派

更新安装按平台形态分派：**Windows 安装版**走完整自动更新——检查到新版本后下载（显示进度），下载完成由用户点击"立即安装"才执行静默安装并重启（绝不随退出自动安装）；**macOS**（含无 Apple 开发者证书的 unsigned 产物，其更新包经完整 ad-hoc 签名、可通过 Squirrel.Mac 签名校验）同样走自动安装链路——下载完成由用户点击"立即安装"执行安装并自动重启；**portable 版**不发起自动检查，更新方式为手动下载新版本。安装阶段失败（如签名校验不通过、环境异常）时，无论自动/手动场景，界面**必须**明确展示失败原因，并提供"打开下载页"（跳转 GitHub Releases）作为兜底更新途径。

#### Scenario: Windows 安装版自动更新全链路

Windows 用户打开 WebDeck，检测到新版后自动下载并显示进度；下载完成弹出更新对话框，用户点击"立即安装"，应用退出 → 静默安装 → 自动重启进入新版本。

#### Scenario: 退出 WebDeck 不自动安装

Windows 用户下载完成但未点击"立即安装"，随后退出 WebDeck——应用正常退出，不静默安装更新（更新保留，下次启动可继续）。

#### Scenario: macOS 点击立即安装完成更新

macOS 用户检测到新版本（unsigned 产物，更新包内 app 签名校验通过），下载完成后点击"立即安装"，应用退出、安装新版本并自动重启进入新版；不要求用户手动下载安装包。

#### Scenario: macOS 安装失败可见并兜底

macOS 用户点击"立即安装"后安装失败（如更新包签名校验不通过），应用不退出、继续可用，界面显示失败原因与"打开下载页"按钮；用户点击后系统浏览器打开 GitHub Releases 页面，可手动下载安装新版本。

#### Scenario: portable 版不自动检查

Windows portable 版用户打开应用，不发起自动更新检查、不显示更新入口，更新方式为手动下载新版本。

### Requirement: 更新检查失败可恢复

更新检查/下载/安装失败不破坏当前版本：下载中断可取消、错误经 IPC 上报、自动调度按指数退避重试；安装仅在用户确认后触发。检查/下载阶段的失败仅在手动场景提示；**安装阶段的失败（下载完成后执行安装时出错）无论触发场景都必须提示用户**，并给出可操作的兜底途径（打开下载页）。

#### Scenario: 下载失败不影响使用

Windows 用户更新下载中断（断网/取消），应用功能不受影响，手动"检查更新"可重新发起下载。

#### Scenario: 自动场景安装失败有提示

macOS 用户经自动检查下载完成并点击"立即安装"，安装失败时界面出现错误提示与"打开下载页"按钮（非静默），应用继续正常运行。
